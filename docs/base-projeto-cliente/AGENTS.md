# Regras do projeto

Antes de atuar, leia nesta ordem:

1. `CODEX.md`
2. `docs/briefing.md`
3. `docs/escopo.md`
4. `docs/decisoes.md`
5. `docs/seguranca.md`

## Regras permanentes

- Responder e documentar em Português do Brasil.
- Não inventar requisitos, dados, métricas, depoimentos ou integrações.
- Não ampliar o escopo sem aprovação explícita.
- Tratar o formulário como entrada e os documentos aprovados como fonte oficial.
- Preservar a tecnologia existente quando ela atender ao projeto.
- Evitar dependências redundantes e abstrações prematuras.
- Validar entradas, autorização e propriedade dos dados no servidor.
- Nunca registrar ou versionar segredos e dados pessoais desnecessários.
- Implementar uma entrega coerente por vez.
- Executar as verificações descritas no projeto antes de concluir.
- Registrar mudanças relevantes em `CHANGELOG.md` e decisões em `docs/decisoes.md`.
- Versionar cada entrega aprovada no Git.

## Conflitos

Quando uma solicitação contrariar uma decisão aprovada, não substituir silenciosamente. Registrar o conflito e solicitar confirmação.
